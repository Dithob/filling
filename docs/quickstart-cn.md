# 字段簿快速上手（国内校招）

面向使用者的最短路径：装一次、备一份简历、之后每次投递点三下。

核心前提：**匹配与填表全部在本地由字段字典完成**，不需要 API 密钥、不联网。AI 只用在「导入简历时把 PDF 文字转成结构化档案」这一件事上，而且默认不启用——不配也能跑完全流程。

---

## 1. 装进浏览器（一次性）

```bash
pnpm install
pnpm build                 # 产物在 .output/chrome-mv3
```

1. Chrome 打开 `chrome://extensions` → 右上角打开「开发者模式」
2. 点「加载已解压的扩展程序」→ 选 `.output/chrome-mv3`
3. 点工具栏拼图图标，把「字段簿」固定出来

> 构建**必须**经 `pnpm build`（内部走 `scripts/run-wxt.mjs`）。直接调 `wxt` 在本机会因沙箱的 `fs.rmdir` 语义问题删掉 CSS 产物并构建失败，详见 README。

## 2. 先拿测试台练一遍（强烈建议，约 5 分钟）

正式投递前先在不重要的页面上把手感练出来：

```bash
python -m http.server 5174 --bind 127.0.0.1 --directory docs/testbed
# → http://127.0.0.1:5174/forms/ats-cn.html
```

`ats-cn.html` 覆盖 39 类中文标签，右侧自带自检面板，能直接告诉你哪个字段没填中。**把这份夹具当成靶场，比在真实投递页上试错便宜得多。**

## 3. 准备一份简历（一次性，长期复用）

点工具栏图标 →「打开工作台」，在「档案」区选一种方式：

| 方式 | 适合 | 说明 |
|---|---|---|
| **上传 PDF → 规则快速抽取** | 已有简历 PDF | 首推。纯本地规则，几秒出结果，直接更新表单 |
| 手动填写结构化表单 | 想逐项校对 | 最准，字段全可控 |
| 导入 `profile.json` | 已有档案 | 换机器、多份简历之间的搬迁方式，导出导入都是它 |

导入 PDF 时会弹出三选：**规则快速抽取（推荐）** / 使用 AI 解析 / 仅保存文件。多数情况选第一个就够。

要用 AI 解析的话：点下去会先让你填 DeepSeek 的 API 密钥（默认模型 `deepseek-flash`，Base URL 收在「高级设置」里），填完立刻开始解析。结果会先过一遍结构校验，不合格会自动让模型修一轮；两轮都不合格就报错，PDF 原文仍然留着，可以随时改走规则解析。AI 解析能拿到规则抽不到的中文字段（民族 / 政治面貌 / 身份证号 / 籍贯 / 紧急联系人 / 英语水平 / 排名 / 培养方式 / 实习时长 / 研究方向），因为它的目标形状就是扁平档案本身。

### 校招专属字段记得补

JSON Resume 没有「政治面貌」这类槽位，它们统一放在 **「扩展字段」** 里维护：

> 民族 / 政治面貌 / 身份证号 / 籍贯 / 微信 / QQ / 紧急联系人 / 紧急联系电话 / 英语水平 / 专业排名 / 培养方式 / 可实习时长 / 实习经历 / 项目经历 / 校园经历 / 获奖情况 / 研究方向 / 兴趣爱好

这里的**键名会直接和页面标签比对**，所以填「政治面貌」比填「zzmm」更容易命中。这也是字典没覆盖时的兜底通道。

填完记得点「保存修改」。

## 4. 确认默认配置（基本不用动）

工作台左侧「快速导航」按区块跳转，三处值得看一眼：

- **设置页里没有 AI 区块了。** 快速导航只有四块：入门 / 档案 / 自动填表 / 高级。AI 不是一种「全局模式」，而是导入简历时的一个选项——不配就永远走规则抽取。
- **自动填表 → 填充策略** —— 默认「只填空字段」，页面上已有的内容不动。想整页覆盖再切「覆盖已有内容」。注意它**只作用于批量的「填写匹配字段」**，手动点单个字段填入时始终覆盖。
- **自动填表 → 字段匹配适配器** —— 国内校招勾上「中文（简体）」。

## 5. 每次投递的固定动作

1. 打开投递页
2. 点工具栏图标 →「打开侧边栏」
3. 首次会问「允许字段簿扫描此页面吗？」→ 点**允许扫描**（不授权就读不到页面内容）
4. （可选）点「重新扫描页面」刷新字段清单
5. 点**「填写匹配字段」** → 批量填充

填完侧边栏会列出每个字段的状态：待处理 / 已填写 / 已跳过 / 失败。**「已跳过」通常意味着页面本来就有内容**（受「只填空字段」保护），不是出错。

## 6. 漏填、填错怎么办

切到「字段审核」tab：

- 点某个字段 → 在「存储的数据」下拉里选值 → 点「填写字段」。手动填入**不受**「只填空字段」限制，会直接覆盖。
- 字段显示「未映射」，说明简历里没有对应数据，或该槽位暂无 profile 字段——去「扩展字段」补上，或直接用下面的手动复制。

切到「手动复制」tab：

- 可搜索简历数据、逐个复制值，粘到页面上任何控件（自定义下拉、富文本、文件上传都适用）。
- 这里也能看已保存的 PDF 预览。

如果填充失败，侧边栏会给出具体原因（如「页面选项里没有匹配项」「自定义控件没有弹出选择面板」「页面拒绝了这次填入」），照着改用手动方式即可。

## 7. 越用越准

- 按 `Alt` 之类的快捷提示、以及在引导浮层里**接受/手改过的内容会被记住**，下次遇到同类字段优先使用。
- 想清理：工作台「高级」→ 字段记忆 →「刷新」/「清除全部」，也可逐条删除。

这一层记忆属于「手动填过的值优先」，是给你个性化纠偏用的。

## 8. 排错速查

| 现象 | 原因与处理 |
|---|---|
| 侧边栏说「未检测到可填写的字段」 | 页面还没渲染完 → 重新扫描；或表单在跨域 iframe 里 |
| 导入时选「使用 AI 解析」却提示没配密钥 | 会先弹出配置窗要 DeepSeek 密钥；填好保存后会接着开始解析 |
| 填不进某个下拉/日期控件 | 实现差异极大，侧边栏会给原因；用「手动复制」粘进去 |
| 显示「需要先授权」 | 回到侧边栏顶部点「允许扫描」 |
| 文件上传没反应 | 确认工作台上传过简历附件，且文件 ≤ 8MB |
| 想让页面高亮更明显 | 工作台「自动填表」→ 高亮覆盖层 → 打开「显示戏剧化的高亮效果」 |

## 9. 已知边界

- **closed shadow root 无法穿透**，这类控件扫不到。
- 扫描需要你主动授权；不想用时关掉侧边栏或点「停止扫描」。
- **AI 解析走 DeepSeek。** 它的 `response_format` 只支持 `json_object`、不支持 `json_schema`，所以字段结构由「提示词形状示例 + 本地校验 + 失败回喂修复一轮」保证，而不是服务端强约束；偶发返回空内容时会自动重试一次。
- 扩展只在你打开侧边栏/触发时读取页面，数据全部存在浏览器本地。
